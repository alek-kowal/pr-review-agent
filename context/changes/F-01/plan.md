# Monorepo Foundations (F-01) Implementation Plan

## Overview

Lay down the pnpm monorepo in the target layout from `context/foundation/tech-stack.md` (apps `web`, `api`, `worker`; packages `core`, `db`, `integrations`, `agents`) with TypeScript, Vitest, ESLint + Prettier with package boundary rules, a Playwright smoke, a GitHub Actions CI workflow and `AGENTS.md`. Every later roadmap item relies on `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:e2e` and CI from here. The roadmap tasks F-01-T1..T9 are the phases 1..9, one to one.

## Current State Analysis

- The repo holds only docs: `context/`, `docs/`, `prototype/` (static HTML/JS/CSS prototype), `.gitignore`. No `package.json`, no code.
- Toolchain on this machine: Node 24.21.0, pnpm 12.6.0, Docker 28.
- `tech-stack.md` flag 1 says "scaffold Fastify at root, then move"; the roadmap overrides it: scaffold straight into `apps/api` while keeping the generator's layout.
- Flag 3: delete the generator's `package-lock.json`; flag 4: replace `node:test` with Vitest.
- WB design tokens live in `prototype/styles.css` (`:root` light block from line 4, dark under `@media (prefers-color-scheme: dark)` line 30 and `:root[data-theme="dark"]` line 52; viz tokens lines 343–345).
- Top bar spec: `docs/03-design-decisions.md` "Approved structure".

## Desired End State

On a clean clone: `pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e smoke.spec.ts` all exit 0, and `pnpm verify` runs lint, typecheck and test in parallel and exits 0. `.github/workflows/ci.yml` passes actionlint. `AGENTS.md` (< 100 lines) states the conventions; `CLAUDE.md` contains only `@AGENTS.md`.

### Key Discoveries:

- Roadmap tasks and their "done when": `context/foundation/roadmap-tasks.md` section "F-01: monorepo-foundations".
- Shared conventions (scope `@pra/*`, commands, env var names): same file, "Shared conventions".
- No runtime fake mode; test doubles only in tests and `@pra/*/testing` (`docs/08-orchestrator-log.md` #4).

## What We're NOT Doing

- No Postgres, Drizzle, pg-boss, pino, `/health` (F-02); no domain rules in core (F-03); no hosting (F-04).
- No theme toggle (S-17), no search or status chip in the top bar (later slices).
- No e2e job in CI (S-01), no deploy job (manual-promotion).
- No push and no merge in this change: the "CI run is green on GitHub" check stays pending for Alek.
- No Turborepo/Nx.

## Implementation Approach

Sequential phases, each one verified before the next. Use official generators (`fastify-cli`, `create-vite`, `shadcn`) and adapt their output instead of hand-writing scaffolds. Latest stable versions of every dependency at install time. Root scripts delegate to packages with `pnpm -r`; Vitest runs once from the root over `test.projects`.

## Critical Implementation Details

- **Generated route tree:** `apps/web/src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin, but `tsc` on a clean clone (and CI) needs it before any Vite run. Commit it, and exclude it from ESLint and Prettier.
- **`pnpm verify`:** `pnpm run --parallel` with a regex (`pnpm run "/^(lint|typecheck|test)$/"`) runs the three root scripts in parallel without a new dependency; it must exit non-zero if any of them fails (verify by breaking one on purpose once).
- **Generators and lockfiles:** run generators with non-interactive flags; delete any `package-lock.json` or nested lockfile they create and keep the single root `pnpm-lock.yaml`.

### Changes Required:

**File**: `apps/api/src/plugins/`, `apps/api/src/routes/`, `apps/api/test/`
