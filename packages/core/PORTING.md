Where each of the 98 tests in `~/Projects/wb-factory/test` (P) goes: the core test that ports it,
the slice that will port it, or why it is not ported. Totals: 98 rows, 52 ported, 40 assigned to
slices, 6 not ported.

**Parity with P is verified** (P-02b, 2026-11-19). Every P test was read next to the P source it
calls. For each ported row the Parity column says whether our test asserts the same behaviour
(`same`, 27 rows), whether core or its test was changed to match P (`fixed`, 14 rows), or whether the
PRD or the design docs decide otherwise (`differs on purpose`, 11 rows, with the source in the note).
Slice and not-ported rows were checked for rules core should already own (`checked`). The
decisions are in `context/changes/P-02-domain-core/change.md` under "P-02b parity pass".

The "P test" column is the line where the P test starts. Ported rows name the Vitest test as
`file › describe › title`; each title carries its P reference and appears in
`pnpm --filter @pra/core test --reporter=verbose`. Slice rows name the roadmap slice
(`context/foundation/roadmap.md`) whose tasks will port the test.
